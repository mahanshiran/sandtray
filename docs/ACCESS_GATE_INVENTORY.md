# Access gate inventory

Workspace audit, September 14, 2026. This inventories real entry points and gaps; it does not enable policy enforcement or certify release readiness. `IsSubscribed` still combines legacy manual/store expiry with RevenueCat and the Android promotion. Backend service switches and relay switches remain independent. Ownership checks must remain separate from plan access.

| Area | Current entry points | Current protection / remaining work |
| --- | --- | --- |
| VIP identity and badges | `BackendClient.IsSubscribed`, `RevenueCatManager.IsSubscribed`, `SceneBootstrapper.MainMenu`, `SettingsRows` | Legacy expiry, SDK state and Android bypass. Badges can remain a summary; they must not decide feature allowances after migration. |
| AI home entry | `SceneBootstrapper.MainMenu.OpenHomeAiEntry` | Still has a broad VIP gate. Replace with `ai.analyze` availability while separating result viewing from report storage. |
| AI provider work | `BackendClient` reflection methods; `analysis/views.py::reflect`; `analysis/metering.py` | Actual service reservation/commit is implemented behind `ACCESS_SERVICE_ENFORCEMENT`. Legacy VIP without a migrated plan deliberately gets migration-pending status. No client success flag can finalize usage. |
| Old usage callbacks | `BackendClient.ConsumeFreeFeature`; `accounts/views.py::FreeTierUsageView` | VIP bypass remains for compatibility. AI/PDF POST callbacks become non-charging when service metering is enabled. Retire only with coordinated legacy access migration. |
| PDF generation and retrieval | `SceneBootstrapper.Reports`, `AnalysisUI`, `analysis/views.py`, `analysis/metering.py` | Server generation metering and durable retries implemented behind the service switch. Retrieval of the same generated result does not allocate a second export. |
| Saved local tables, duplication/import/archive/delete | `SessionManager.cs`, `AutoSave`, `Versions`, `Archive`, `Cloud` | Opt-in account scope protects local paths and stale handles. Existing tracked table edits/renames/deletions use the capacity journal; completed deletion queues release. New allocation, initial inventory, duplicate/import/guest limits and retry/recovery UI remain unfinished. |
| Old account-owned cloud-table API | `boards/views.py`, `boards/capacity.py` | Slot reconciliation, atomic creation/deletion and idempotency implemented behind `ACCESS_CLOUD_TABLE_ENFORCEMENT`. This is distinct from the newer cloud-version backup API. |
| Saved local reports | `SessionManager.AppendAnalysisReport`, report workspace/templates/review partials | Report authorship/revision checks exist. `reports.capacity` is not integrated into local persistence. Do not count PDF export copies as newly authored reports. |
| Remote analysis records | `analysis/views.py::AnalysisRecordViewSet`, serializer | Authenticated records are queried by requester. Persistent report capacity and full association validation still need integration; do not claim these records prove local report ownership. |
| Report delivery/receipt | `SceneBootstrapper.ReportNotifications`, `ReportWorkspace`, `community/report_views.py` | Author/practitioner and recipient-copy rules remain required. New deliveries and changed revisions check `reports.share` behind disabled `ACCESS_REPORT_SHARING_ENFORCEMENT`. Unchanged retries and recipient reads remain available after sender expiry. Local report capacity and UI gates remain unfinished. |
| Report templates | `SceneBootstrapper.ReportTemplates`, `ReportTemplateStore` | Existing account-specific templates and field validation; `reports.templates` capability still needs consistent entry-point integration. |
| Practitioner client records | `SceneBootstrapper.ClientNavigation`, `Clients`, `ClientRecordStore`; `accounts` client routes | Navigation still uses psychologist role. Local scoped store is available; `clients.manage` and `clients.capacity` are not wired across all operations. Buying access does not verify professional identity. |
| Built-in catalog | Public/library catalog routes and Unity catalog registry | Built-in/public access is deliberately not a VIP gate. Keep ownership checks on private assets independent. |
| Custom catalog upload | `CatalogUploadButton`, upload UI, `catalogs/views.py::upload_asset`, catalog object viewset | Optional client subscription gate and backend ownership/file-size validation. Count/byte capacity, orphan uploads and custom-asset authorization need coordinated work; an uploaded binary and a catalog entry are separate resources. |
| Replay listing/playback/recording/export | `SceneBootstrapper.Replays`, `SessionRecorder`, `ReplayVideoExporter` | Scoped paths implemented; VIP note does not constitute enforcement. `replays.record` and `replays.play` need separate gates and a recovery policy for existing recordings. |
| Hosting admission and runtime | `SceneBootstrapper.HostJoin`, `NetworkBootstrapper`, `accounts/relay.py`, `hosting.py`, `RelayServer/HostingMeter.cs` | Tickets authenticate identity/purpose. Runtime entitlement and monthly time are enforced by bounded hosting leases only when backend/relay rollout switches are enabled together. |
| Joining | Relay join ticket, room code/admission and relay protocol | Logged-in, active users may join without a paid plan. Host approval/security remain required; never charge guest hosting time. |
| Cloud backup/version storage | `SceneBootstrapper.Cloud`, `boards/cloud_views.py`, `cloud_service.py` | Owner checks and independent cloud record/byte limits implemented behind `CLOUD_RECORDS_ENABLED`; preserves owner recovery after expiry. |
| Cloud recipient sharing | Cloud share/revoke/inbox APIs | Fixed reviewed scene versions, recipient/expiry/revocation checks. Full share/viewer UI and custom-asset rights remain unfinished. |
| Offline local capacity | `accounts/access_offline.py`, `access_offline_views.py` | Metadata-only signed leases, explicit release and current-policy reconciliation implemented behind a disabled switch. Unity journal, bounded retries and reusable single-file coordinator are implemented and tested. Actual table/report/client entry-point adapters, rename/import handling and initial inventory reconciliation remain incomplete. |
| Manual grants and credits | `access_service.py`, `access_admin.py`, `access_credits.py` | Signed previews, exact duration presets, audited grants/overrides/credits, independent support-read permission. Actual service operations must opt into this resolver. |
| Sample code | `SubscriptionExample.cs` | Still demonstrates the legacy VIP API. Update with the final capability client gateway when it exists; do not copy this sample as new enforcement. |

## Migration order

1. Finish local inventory reconciliation, durable local lease journal and creation/deletion integration before enabling local capacity.
2. Publish an explicitly reviewed legacy access policy and reconcile manual/store sources and usage; do not infer unbounded allowances from old VIP.
3. Switch server effects first, then UI capability checks with account-bound freshness/offline rules. Missing APIs must not silently grant unlimited access.
4. Remove the Android blanket promotion only when a replacement promotion/grant policy works on both current and supported old clients.
5. Validate physical-device recovery, billing and relay cutoff separately from automated backend tests.
